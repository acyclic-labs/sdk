Run against the lockfile-pinned native hosts and three matching prebuilt executables:

```sh
npm ci --prefix plugin/tests/hosts
E2E_SOURCE=FULL_SOURCE_COMMIT node plugin/tests/hosts/native-pairs.mjs codex /absolute/graphcoder /absolute/harness-mock-model /absolute/acyclic /absolute/new-output PAIRS
E2E_SOURCE=FULL_SOURCE_COMMIT node plugin/tests/hosts/native-pairs.mjs claude-code /absolute/graphcoder /absolute/harness-mock-model /absolute/acyclic /absolute/another-new-output PAIRS
```

`PAIRS` is the explicit positive experiment count. Each adjacent block of two pairs randomly chooses its first bare/installed order and reverses it for the second pair. An odd final pair retains its chosen order without inventing a balancing sample. Each pair gets a fresh workspace/profile and the existing installed-host setup. This interleaves launch order while leaving setup outside each measured launch; it does not establish cold-cache conditions. Codex changes plugin registration only when the next leg requires a different state, so an installed-first pair does not reinstall an already registered package.

These commands use only the shipping loopback mock. Installation, original workspace ownership and policy come from the shared installed-host scenario. Both legs use the same exact installation, profile, source, shell command, file bytes and host version. Codex removes and reinstalls the exact admitted package through its native plugin manager outside both measured launches; Claude omits its plugin directory on the bare leg. No command-line plugin-enable override is treated as evidence of tool removal. The script requires both model steps exactly once and the real native shell's file effect and final answer. Codex must emit its original completed turn with an assistant answer; Claude must emit its successful native result. An answer in intermediate output without that terminal refuses the sample. The caller must retain its enclosing original process-custody completion receipt alongside `pair.json`; Node close alone does not prove descendant retirement.

`pair-N/pair.json` retains both raw process samples in actual launch order and records `launch_order` in the v2 pair format. Delta always means installed minus bare, independent of launch order. `pairs.jsonl` indexes only completed pair files; an interrupted or refused pair has no completed index entry. `phases.json` in each pair directory also retains incomplete original observations when admission fails. `E2E_SOURCE` binds the consumer source and `E2E_ARTIFACT_SOURCE` binds reused prebuilt executables, alongside their original hashes. Fixed first observations come from the existing process pump, stdin writer, transcript writer and terminal promises. It records actual stdin write admission/completion, owner-handle finish, stdout/stderr EOF, first transcript write, observed exit and original closed. These boundaries can overlap: file-write completion is not pipe arrival, handle closure is not proof the child consumed EOF, and an enclosing host's status is not a nested root's status. No linear order is imposed on EOF and exit. Missing boundaries, failed terminals, wrong source or unpaired bytes fail admission. The launch-to-closed delta is a process measurement; it is never a warm-turn or shell-execution sample. Setup and case durations remain separate from the process offsets.

The observation state is fixed per active process and retires at its original terminal. The batch retains one pair at a time, one random order bit and one ordinal; index output grows with the explicitly requested results. It appends one index record per completed pair, with no durability barrier. No second reader, transcript, process owner, timer or control request is added. The shared pump adds one inline metadata callback per fixed first boundary, with no additional IO or payload copy. Phase projection adds fixed scalar storage and one result object per sample; there are no scans over historical operations. Original channel/EOF/exit producers and physical cleanup remain responsible for progress. Existing real-child controls cover dropped/destroyed output and retained observer failure; the paired control runs both launch orders through real pipes and rejects missing EOF, foreign source, reused operation, duplicate leg and unequal result bytes. It does not execute native hosts or qualify native latency distributions.

Pi's pinned native Responses implementation rejects an empty auth result before HTTP. The fixture now calls that original provider/auth/client path and retains its typed `UNSUPPORTED_NATIVE_KEYLESS_PROVIDER` cause. No sentinel credential or header rewriting is permitted. `node --test plugin/tests/hosts/keyless-pi-provider.test.mjs` checks both the actual pinned provider and coding-agent CLI, their original refusal and zero HTTP dispatch. The CLI may exit zero after an error turn, so acceptance reads its original assistant terminal; it is not a positive installed-Pi qualification. A native release with a supported keyless interface is required for that positive scenario.

For an authorized live Codex experiment, append `--live /absolute/nonsecret-login.json --prefix-turns` to the Codex command. The login descriptor uses the same existing native profile/provider/model contract. Each bare/installed leg starts a fresh thread, completes the original shell task, and repeats that task by explicitly resuming its original `thread.started` ID. Missing, duplicated or changed thread identity refuses continuation evidence. Both turns must independently finish successfully and produce the original exact file bytes. Fresh threads must differ between the two legs. The same native package, model, profile, workspace, policy and prompt are held throughout the pair; plugin registration changes only between legs, outside measurement.

This opt-in mode writes `acyclic.native-prefix-pair.v1`. Each leg's `turns` retains its fresh and resumed original terminal, session ID, process phases and transcript references. Codex's original `turn.completed.usage` supplies reported input, cached-input and output tokens; an absent field stays absent. It does not infer cache residency, cache misses, request-prefix equality or time to first token from session reuse or process duration. `provider_cache_state` remains null. The native host owns its renderer, so `sdk_prefix_counters` also remains null: SDK continuation/hash counters cannot measure an external host's encoding work. The existing SDK renderer wire/allocation and retained-prefix controls remain the separate evidence for those operations. Resuming adds history, so these samples do not isolate provider cache benefit from context growth. `resumed_turn_pairs` counts two original identity-checked continuations; `warm_turn_pairs` remains zero because these are separate processes.

The experiment performs four native launches per pair instead of two, with one prompt write, original completion wait, effect removal/read and phase snapshot per turn. It retains four turn records per active pair and one original terminal reference per decoded turn. There is no second JSONL parse, process reader, renderer, durability barrier, readiness probe or history scan. Cancellation, EOF and process retirement use the original shared process scope. `node --test plugin/tests/hosts/native-completion.test.mjs plugin/tests/hosts/process-phases.test.mjs` exercises the retained real-host corpus/fuzz entry and real process pipes, including missing/foreign thread, omitted usage, failed terminal and incomplete phase controls. Those controls do not qualify a live latency distribution.

Warm native turn, tool begin/terminal, fork/merge and selected-root phase joins still require their original public host producers. Process samples cannot fill those fields. Live execution preserves the original profile, credentials, policy and scenario oracles.
