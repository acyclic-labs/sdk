# Unlink completion credit

Run `node rust/proofs/qualify.mjs native-unlink-completion-credit`.

Bug class: accepting a namespace mutation before funding its cached-binding retirement can return a resource refusal after the mutation took effect. The original real shared-source unlink control reproduced this with exhausted item credit: namespace removal and the retained open-file contents both passed before the completion assertion failed. The search `rg -n 'remove_binding\(|\.unbind\(' rust/crates/filesystem/src/native_mount/fuse --glob '*.rs'` identifies the shared binding-removal implementation and its lookup, replacement and unlink callers.

The shared projection state now prepares the original binding position and reserves the exact shifted bytes before source removal. Installation consumes only that retained reservation. The names fence prevents binding-position changes between preparation and installation; FORGET may remove the entire original inode, in which case installation performs no removal and returns its unused credit. Inode numbers are not reused, and the path index is removed only if it still names the original inode. The installer adds no binding or inode, so it cannot resurrect a forgotten one.

Area cleanup: both immediate unbinding and deferred unlink completion use one preparation and installation implementation. The former fallible post-removal copy recording and redundant fallible inode removal are deleted. The existing real source-adoption observer and write-policy boundary control serves rename and unlink; no second fixture or producer is introduced.

The standalone test that manually removed a source name before asking for detached-handle allocation is deleted. The retained production inverse exercises the actual unlink entry point, and the generated allocation-prefix property preserves the pre-effect refusal check. Those controls cover the real operation without maintaining a separate reenactment of its former ordering.

The copy-credit cut uses a real hard link, retaining the original binding before its surviving alias so unlink must shift a binding. After actual source adoption, the existing callback guard retains all remaining copy credit from the original ledger. The test checks source absence, original open-file contents, the surviving alias and its cached binding, and successful completion. A separate item-credit cut retains the original red oracle. The Git-generated production inverse moves preparation after the accepted source effect and detached-handle installation; the unchanged copy-credit control must reject that ordering. The restored run also retains rename completion and the generated allocation-refusal-prefix property.

The original restored copy-credit control also exposed a shared reservation defect: completing reserved work refunded its allowance before recording the actual work. Recording reconciles retired allocation owners, whose optional registry compaction could then consume that released allowance and poison the original ledger. Completion now reconciles while its credit remains held, then transfers the reserved amount to actual work under the same original ledger lock. Recording uses one shared implementation, including resource attribution and completed work when reconciliation fails. The second Git-generated inverse restores the original refund-before-reconciliation order at `DemandWork::complete`; the same real unlink control requires the original ledger to remain usable. The census `rg -n 'fn complete|\.complete\(|record_reconciled' rust/crates/filesystem/src/demand rust/crates/filesystem/src/materializer` joins native I/O and retained completion callers to this one boundary. No consumer increases its allowance or maintains another ledger.

The shared completion correction adds no reconciliation pass, ledger lock, allocation, copy, syscall, durability barrier, round trip or wait: the existing reconciliation precedes the refund instead of following it. Optional registry compaction remains governed by its free credit. Its existing scans are not constant-time operations, and this change makes no broader complexity claim. The two retained inverses independently check pre-effect funding and protected completion credit; the generated refusal-prefix property checks progress by returning a refusal before the actual mutation, with no new wait or event producer.

Required binding work is unchanged: one cached-path lookup, a scan through the matched inode's binding prefix and `(binding_count - removed_index - 1) * size_of::<Binding>()` shifted bytes. That scan and its possible refusal now precede the source effect; the shifted-copy allowance is reserved there and recorded on installation. The former copy admission and recording used two ledger visits; reservation, completion and returning unused credit use three, plus the completion's private reservation mutex. Retaining the original work context adds bounded reference-count operations. These costs secure completion credit against concurrent consumers. There are no added syscalls, durability barriers, round trips, heap allocations, path copies or waits. The original ledger is retained in the bounded stack-owned completion. This preserves the existing linear binding-vector costs; it does not prove constant whole-unlink cost or native kernel notification safety.
