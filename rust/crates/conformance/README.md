# acyclic-conformance

Reusable black-box qualification workloads for public Acyclic provider contracts. Run the relevant suite against your provider implementation before claiming protocol compatibility.

```sh
cargo add acyclic-conformance --dev
```

The crate exposes Filesystem workload vectors, a minimal Filesystem smoke check, canonical Objects and Stream provider suites, a Machines lifecycle suite, and machine-readable Harness reports and qualification receipts. Run provider suites against fresh, disposable state; their resources and idempotency identities are deliberately retained for exact replay checks.

Run the local consumer gate from the SDK root with `python scripts/qualify-local.py` (use `python3` where needed). It validates the in-tree `plugins/acyclic-agent-workspaces` control plane, runs a public Filesystem fixture capture/restore roundtrip, and emits one JSON report. The report also contains four verified Filesystem write measurements, crossing individual versus batched writes with full-flush versus barrier durability. Use `--plugin-root PATH` to validate another compatible plugin checkout or `--sdk-only` to omit the plugin. `--seed N` rotates the model histories; `--max-seconds N` bounds SDK case execution. The runner uses one platform-specific Cargo build cache (on WSL, under `~/.cache/acyclic-lab/target` to avoid Q: mount overhead) and preserves the host's normal downloaded dependency cache. It never caches test state or pass results. The complete cold command is capped at 15 minutes, and the SDK case budget defaults to 5 minutes.

The gate also starts `s3-fixture`, a local HTTP server built only from the public Filesystem S3 API. It runs a pinned boto3 `SigV4` consumer and 36 selected tests from Ceph `s3-tests` revision `5522d1c351f75bc00ae0f64f742f3f095f5939d9`. The cases cover authenticated bucket lifecycle, naming, isolation and recreation, both listing protocols, pagination and URL encoding, object operations, bulk deletion, copy, multipart upload, and ranges. `ListObjectVersions` exposes unversioned objects with the S3 `null` version; reads reject any other version ID. The shared Python environment and Ceph source checkout are pinned and cached, while every server store and bucket is disposable. This is a bounded compatibility selection, not a claim that all Ceph S3 tests pass.

The same gate measures signed `ListObjectsV2` calls through boto3 for 64 one-object pages, using both dashed and flat keys. Each result records first-page median latency and full-walk time in the report's `benchmarks` array. The SDK now stops listing after the requested page and a witness; a private inclusive tree seek resumes direct-child object markers in bounded work. Dashed keys can still require replay from the ordered frontier when an earlier directory name could flatten after the marker. These timings are evidence, not a performance threshold; removing that remaining replay requires an ordered logical-key index or a structural cursor.

`scripts/ceph-s3.py --known-gaps` retains three failing Ceph cases as reproducible design probes. Two require an S3 object key to coexist with another key that uses it as a path prefix; the current direct Filesystem path mapping cannot represent both. One requires the single-part MD5 `ETag`; the current strong validator is tied to the immutable generation. [The migration and acceptance design](S3_STORAGE_DESIGN.md) defines the next implementation pass. Avoid translating either failure into a false success.

The same `qualify` binary owns the SDK's Filesystem fixture and diagnostic commands: `fixture`, `roundtrip`, `corpus`, `bench`, `restore-gen`, `mount-smoke`, `mount-smoke2`, `mount-hold`, and `source-probe`. They consume public SDK APIs. The plugin control plane consumes the same public APIs and keeps its end-to-end tests in its own crate.

On Windows, the shared gate also builds a debug qualifier and captures a one-byte file on its default main-thread stack. This retains the regression for oversized nested mutation futures, which optimized builds can hide. The gate rotates its deterministic seed each UTC day unless `--seed` is given, and applies a 5-minute warm or 15-minute cold limit based on the required binaries in the shared build cache. `--max-seconds` overrides that limit.

For a measured Filesystem consumer, run `cargo run --release -p acyclic-conformance --features local-runner --bin bench-fs -- --writes=64` from `rust/`. Add `--batch` to publish one transaction, or `--barrier` to compare the local durability policy. The benchmark verifies the resulting files after timing and emits one JSON measurement. The combined gate checks that all four modes succeed and reports their timings; it does not yet impose a performance threshold.

The first [cross-host baseline comparison](benchmarks/2026-09-18-local-fs.json) records three warm full-flush samples from the preserved pre-lazy revision and this lab branch. This small workload did not establish a reproducible performance shift; continue comparing real consumers and add CPU, memory, and allocation measurements before setting regression thresholds.

The filesystem workload corpus is not yet an executable backend conformance runner, and Harness is currently the only family with report-to-receipt validation. The exported Objects inventory is a checklist, not a per-case execution receipt. Do not interpret a passing smoke check as full Filesystem qualification. See the [API](https://docs.rs/acyclic-conformance/latest/acyclic_conformance/) and the [protocol directory](https://github.com/acyclic-labs/sdk/tree/main/proto) for the underlying contracts.
