# Shared registry control

`registry-cold-open.patch` was generated by deleting the production cache-hit
return in `src/native_mount/registry.rs`. Apply it from the repository root.
Run the existing shared-registry model with the normal Loom compiler wrapper:

```sh
RUSTC_WORKSPACE_WRAPPER="$PWD/scripts/loom-rustc.sh" cargo test --locked -p acyclic-fs --features model-checking --lib native_mount::fence::models::shared_registry_descriptor_serializes_threads_before_the_kernel_lock -- --exact
```

The mutation must fail the unchanged identity assertion, `each mount reopened the
registry directory and lock`. Compilation errors, unrelated panics and timeouts
are not this negative control. Restore the source and require the same model to
pass. It checks the production cache and admission path, with modeled kernel
locking; actual operating-system lock behavior requires native conformance.

## Recovery custody control

`recovery-early-release.patch` was generated by releasing the original destination
fence ahead of driver recovery in `NativeRecoveryState::finish_with_work`.
The ordinary source has no alternate ordering selected by the model. Apply the
mutation from the repository root, then run the unchanged recovery model:

```sh
RUSTC_WORKSPACE_WRAPPER="$PWD/scripts/loom-rustc.sh" cargo test --locked -p acyclic-fs --features model-checking --lib native_mount::disconnected::models::real_recovery_owner_keeps_fence_through_helper_exit_with_negative_control -- --exact
```

The mutation must fail one of the original custody assertions:
`helper detached a live remount after early fence release`,
`remount acquired the fence before helper exit`, or
`recovery fence released before helper exit`. A stack overflow, branch-budget
failure, compiler error, or unrelated panic does not qualify the control.
Restore the source and require the same model to pass. The model uses actual
recovery and fence ownership with modeled kernel calls; it does not establish
native process or mount conformance.

native conformance test. Apply one patch from the repository root, run its exact
selector, then reverse the patch and require the same selector to pass:

```sh
cargo test --locked -p acyclic-fs --all-features --lib SELECTOR -- --exact --include-ignored --nocapture
```

## Existing-record candidate control

`record-candidate-before-read.patch` moves the actual candidate acquisition ahead
of the existing-record read in `HostRoot::read_or_publish`. The ordinary source
has one lazy path, without a probe-selected eager implementation. Apply the
mutation from the repository root and run:

```sh
cargo test --locked -p acyclic-fs --all-features --lib native_capture::held_root_tests::reading_an_existing_record_never_generates_another_candidate -- --exact
```

The unchanged property must fail `an existing record requested another candidate`:
its real record already exists and its candidate provider retains the original
PermissionDenied refusal. Restore the source and require the same property to
pass. All 16 generated reader-count cases share one immutable native publication;
every real read still checks exact bytes and the unchanged candidate count.
The initial unavailable provider must retain its cause and leave no record, and
the first successful publication must call its provider exactly once. Compiler
errors, timeouts and unrelated panics do not qualify this control.
