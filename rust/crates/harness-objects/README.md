# Harness Objects adapter

`ObjectContentStore` binds one Objects bucket and one Harness volume to an exact, trusted provider identity and the owner's signed authority. The owning provider supplies its verifier and owner scope; attached readers supply only their narrower signed scope. The binding publishes immutable, version-pinned `FileRef` values for the original owner and resolves exact retained versions with SHA-256, length, media type, and display-name checks. It also validates complete canonical attachment manifests and their members. Objects remains unaware of Harness agents; the binding is the authorization boundary. Do not accept the expected provider identity, verifier, or owner scope from an untrusted reader.

The same owner-bound store can be installed as a `ForkCaptureProvider` and `ForkSeedVerifier` for its exact Objects provider identity. `artifact_ref(file)` selects a pinned object version without copying the body; capture and publication use metadata-only `head` checks. The artifact reference is not a read grant: resolving its bytes still requires an authenticated volume scope. A provider identity registered in a composite fork verifier must have one adapter that covers every selected bucket under that identity.

`ObjectContentMountResolver` (also available as `ObjectContentRouter`) lazily routes refs across separately registered `ObjectContentStore` buckets. Register each store with its owner-authenticated or owner-delegated reader scope; mounting rechecks that scope against the exact `FileRef` and returns the verified `ContentGrant` together with the owner reader. A ref alone never authorizes a read, and the mounted reader repeats the grant check when fetching bytes.
