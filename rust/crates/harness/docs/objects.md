# Objects adapter

Enabled by the `objects` feature.

`ObjectContentStore` binds one logical Objects v2 bucket and one Harness volume to an exact, trusted provider identity and the owner's signed authority. The owning provider supplies its verifier and owner scope; attached readers supply only their narrower signed scope. The binding publishes content-addressed `FileRef` values for the original owner. The generic Harness file revision carries a digest of the descriptor and display name, including the descriptor's SHA-256 and byte length; it is not an Objects version or `ETag`. Complete immutable keys are published with `IfAbsent`. Reads validate bytes, length, media type, display name and content identity. The adapter also validates complete canonical attachment manifests and their members. Objects remains unaware of Harness agents; the binding is the authorization boundary. Do not accept the expected provider identity, verifier, or owner scope from an untrusted reader.

The same owner-bound store can be installed as a `ForkCaptureProvider` and `ForkSeedVerifier` for its exact Objects provider identity. `artifact_ref(file)` selects the immutable content key with no Objects version field; capture verifies bounded bytes and metadata against its content identity. The artifact reference is not a read grant: resolving its bytes still requires an authenticated volume scope. A provider identity registered in a composite fork verifier must have one adapter that covers every selected bucket under that identity.

Presence and a content digest do not establish indefinite residency. A durable service accepting these references must record its acceptance intent and adopt private Objects retain claims before publishing the durable reference, and reconcile pending intents or terminal aborts. This SDK adapter does not create a public retention API or establish Cloud acceptance. Eventual reads can temporarily fail after publication; callers may reconcile using the same operation identity. No automatic mutation retry is performed.

`ObjectContentMountResolver` (also available as `ObjectContentRouter`) lazily routes refs across separately registered `ObjectContentStore` buckets. Register each store with its owner-authenticated or owner-delegated reader scope; mounting rechecks that scope against the exact `FileRef` and returns the verified `ContentGrant` together with the owner reader. A ref alone never authorizes a read, and the mounted reader repeats the grant check when fetching bytes.
