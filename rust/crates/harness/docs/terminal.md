# Native GraphCoder terminal

`graphcoder` remains a binary in `acyclic-harness`, not a second product engine.
Build/install with `--features terminal,filesystem-local --bin graphcoder` for
actual persistent local sessions. `--features terminal` alone retains explicit
presentation playback and rejects native sessions as unavailable.

## Actual native composition

`graphcoder --session CONFIG.json` opens the existing `Fs::local` and
`LocalStream` providers, registers the public `StockTurnMachine`, and opens the
ordinary `FilesystemTaskRuntime`. No UI journal, workspace registry, effect
ledger, fork/task ID mapping or orchestration engine is introduced. Plain prompt
text queues a typed admitted task; `/run TASK` explicitly starts its existing
fenced worker without blocking prompt input. At most 16 transient worker handles
and a one-line input channel are retained. Displaying, inspecting and reopening
never dispatch queued work.

The bounded JSON configuration is generated by the trusted composition owner,
not inferred from a fork reference, task label or environment credential. Its
fields are `filesystem_root`, `stream_root` (absolute paths),
`filesystem_provider`, `stream_provider`, `private_volume`, `owner`,
`observed_authorities`, `generation`, `limits`, `run_limits`, `session_limits`,
`concurrency`, and optional `deterministic_delay_ms` (0–5000). Each authority
binding contains `authority`, `issuer`, `key` (32 bytes), and an original signed
`scope`. Keep this explicit credential file private. The producer must already
have created/published the private volume and any recursive workspaces, with real
provider authority. Drop producer handles before starting the local consumer;
providers retain their normal exclusive ownership rules.

The installed credential-free model is explicitly `graphcoder-deterministic /
request-digest @ 1`. It computes output from the exact admitted request digest,
uses declared conservative byte-token upper bounds, and reconciles only a
matching retained event prefix. It is ordinary execution through the model
command adapter, not prerecorded wire playback or a live-model quality claim.
The optional bounded delay is retained in model options so an installed process
can be killed during a real model dispatch. With nonzero delay, a flushed stderr
`deterministic-dispatch` barrier identifies entry into the actual provider after
model-start journaling; the qualification owner must kill before completion.
Live-model, native-process, remote
and unbound optional adapters remain explicitly unavailable. REPL/code-mode and
Tree-sitter are outside the original GraphCoder delivery scope.

## Interaction and bounded inspection

- Plain text queues a stock root task. `/parent TASK` selects a real retained
  parent; `/parent root` returns to root admission. Children inherit the actual
  admitted parent context and grants through the public task context.
- `/queue FILE` admits a typed `WorkflowCommand` JSON. Admission and command
  identities are distinct; the attempt identity is flushed before admission.
  `/reconcile OPERATION` observes a lost acknowledgement without resending input.
- `/run TASK` drives this exact task, never an unrelated ready task. Before
  dispatch it flushes `lease-json-hex=...`, the original typed `WorkLease` JSON
  bytes encoded as hex. Decode and retain those bytes externally if exercising a
  process fault. `/resume FILE` consumes that original lease JSON and lets the
  canonical worker verify it; it does not guess or replace ownership.
- Input, queued steering, inspection and `/cancel-task TASK` remain responsive
  while ordinary workers execute. Task cancellation delegates to the original
  typed host and shows the retained admission operation; it requests cancellation,
  never claims the active provider has stopped.
- `/outcome TASK` displays the actual durable outcome and its distinct admission
  operation. `/children FILE` accepts `{task, revision, after}` JSON and reads
  only one direct-child page, at most 16 entries. Continuations must carry the
  observed revision; no complete descendant tree is hydrated.
- `/next` reads one verified activity page. `/cursor FILE` selects an explicit
  Protobuf Resume `ClientFrame` for archival paging. Only one authority cursor is
  accepted; each page is bounded by 16 events and 64 KiB encoded response.
- `/file FILE` displays a granted immutable `FileRef` JSON, at most 64 KiB.
  `/diff FILE` accepts `{before, after}` exact refs and displays the bounded
  before/after UTF-8 versions, at most 32 KiB each. This is presentation, not a
  replacement diff/merge algorithm or automatic root writeback.
- `/request FILE` submits one already scoped Protobuf `ClientFrame`.
  `/input FILE` requires the conversation-message command discriminator;
  `/approve FILE` requires the exact interaction-resolution command; `/cancel
  FILE` requires a Cancel frame. The same native/WASM codec validates canonical
  bytes, discriminators, protocol and identity. Existing aggregate, fork,
  merge, interaction and coordinator authorities still make the decisions.
- `/reopen` drops the actual provider/runtime handles before opening the same
  composition. It rejects active frontend worker handles instead of silently
  cancelling them. Its success does not imply pending work completed, stopped or
  was resent. Process reopen likewise uses the explicit original config.
- `/back N` displays one transient retained page. Scrollback evicts by both
  count (64 pages) and total bytes (256 KiB). Oversized rendered pages fail
  before output; evicted history requires explicit archival demand.

Transcript, interaction/approval, fork and merge layouts consume the existing
`EventPayload` types. References remain lazy; viewing a ticket grants no response
rights. All provider-controlled terminal controls are escaped. Cancellation
acknowledgement is never labelled confirmed cancellation; admission is never
labelled completion. `/quit` drops presentation without claiming effect
quiescence. `/help` prints the complete control table.

## Explicit playback

`graphcoder --fixture wire [--headless]` reuses the existing
`conformance/native-wasm-event-v2.json`. Its banner always says UI playback only.
`/next`, `/reset`, `/back`, `/request` and `/quit` share the presentation path;
all mutations remain unavailable. Playback is not persistence, recursive
runtime, model, filesystem or grant evidence. It starts at the fixture's
explicit predecessor, not a fabricated missing history.

## Installed and PTY qualification

After integration, the validation owner should run:

```text
cargo test -p acyclic-harness --features terminal,filesystem-local --bin graphcoder
cargo clippy -p acyclic-harness --features terminal,filesystem-local --bin graphcoder -- -D warnings
cargo install --path rust/crates/harness --locked --features terminal,filesystem-local --bin graphcoder --root ABSOLUTE_INSTALL_ROOT
node scripts/test-graphcoder.mjs ABSOLUTE_INSTALLED_BINARY
node scripts/test-graphcoder.mjs ABSOLUTE_INSTALLED_BINARY ABSOLUTE_NATIVE_CONFIG
```

Retain exact source, installed binary and suite hashes, argv, exit status and raw
output. The existing script's pipe/headless checks are installed process evidence,
not PTY evidence. Do not substitute a pipe, mocked terminal or unit test for the
required actual Windows ConPTY / Linux / WSL / macOS PTY interaction.

The optional native configuration lane requires a producer-created volume,
task-spawn/model/control grants, a four-task/two-depth-or-greater session ceiling,
and an explicit 1000–5000ms provider delay. It exercises installed root, two-child
and grandchild admission, lazy direct-child inspection, responsive queued-sibling
cancellation during model execution, actual model process death, original-lease
reconciliation, and provider/process reopen without redispatch. It is not the
broader recursive workspace/writeback or platform PTY lane.

For an actual installed PTY, launch the absolute installed binary with
`--session CONFIG.json` in the qualification runner's real native PTY (for
example its `pty: true` process option). Send a root prompt, retain the returned
**task** and **admission-operation** separately, select that task with `/parent`,
queue two children, select one child and queue a grandchild. Page only the
selected task's direct children. Run explicit task IDs, inspect outcomes, reopen
providers, and re-observe the same task IDs without another generation/effect.
Also exercise queued `/input`, scoped cancellation, original lease reconciliation,
prepared isolated file/edit/fork/merge requests, exact diff refs and scoped
approval resolution from the shared public-runtime scenario producer.

Fault controls: configure a nonzero bounded deterministic delay; kill the
installed process after its flushed original lease claim, reopen with the same
config, and supply that exact retained lease for reconciliation. Negative controls
must include a forged scope/owner, stale generation/revision, wrong command kind,
wrong task identity, altered lease/fence, ungranted file/ref, denied approval,
terminal-control payload and oversized input/page. A timeout/launch failure is
never an acceptable negative-test result. Native producer fault injection owns
interrupted publication, filesystem dispatch and merge acknowledgements; UI code
does not invent such outcomes or automatically repeat them.

No new compile, unit, installed, PTY or platform gate was run during this source
slice. Final-main native/Chromium/WASM and recursive workspace/writeback evidence
remain mandatory for their corresponding claims. The root-to-two-children-to-
grandchild task controls do not by themselves qualify the broader workspace,
context/summary, approval, merge, writeback or cross-platform scenario.
