# Native GraphCoder terminal

`graphcoder` remains a binary in `acyclic-harness`, not a second product engine.
Build/install with `--features terminal,filesystem-local --bin graphcoder` for
actual persistent local sessions. Add `native-execution` for the full installed
recursive fixture and native root writeback. `--features terminal` alone retains
explicit presentation playback and rejects native sessions as unavailable.

## Actual native composition

`graphcoder --session CONFIG.json` initializes native I/O services before opening
the existing `Fs::local` and `LocalStream` providers. With `native-execution` it
also initializes native mount services before finite filesystem operations. It
registers the public stock-turn, mailbox-model and fork-preparation machines and
opens the ordinary `FilesystemTaskRuntime` with the shared configured recursive
tool source and resource-creation provider. No UI journal, workspace registry,
effect ledger, fork/task ID mapping or orchestration engine is introduced. Plain prompt
text queues a typed admitted task; `/run TASK` explicitly starts its existing
fenced worker without blocking prompt input. At most 16 transient worker handles
and a one-line input channel are retained. Displaying, inspecting and reopening
never dispatch queued work.

The configuration is bounded to 1 MiB and generated by the trusted composition
owner, not inferred from a fork reference, task label or environment credential.
Its fields are `filesystem_root`, `stream_root` (absolute paths),
`filesystem_provider`, `stream_provider`, `private_volume`, `owner`,
`observed_authorities`, `generation`, `limits`, `run_limits`, `session_limits`,
`concurrency`, optional `deterministic_delay_ms` (0–5000), `fork_sources`,
`tools`, and `native_publications`. Each authority binding contains `authority`,
`issuer`, `key` (32 bytes), and an original signed `scope`. Keep this credential
file private. Each `fork_sources` entry retains the original authenticated
caller/snapshot/owner/project tuple; checkpoint-backed preparations use the
canonical runtime's retained source resolver, never a latest-head fallback.
`tools` contains finite configured `callers`, `forks`, `merges` and a declared
`content_budget`, consumed by the same native/browser recursive tool source.
Empty tool bindings confer no caller capability. `native_publications` binds
the original root, plan, source-root identity, generations and finite work
budget; without `native-execution`, a nonempty publication binding is explicitly
unsupported. The producer must have created/published volumes and workspaces
with real provider authority. Drop producer handles before starting the local
consumer; providers retain their normal exclusive ownership rules.

The installed credential-free model is explicitly `graphcoder-deterministic /
request-digest @ 1`. It computes output from the exact admitted request digest,
uses declared conservative byte-token upper bounds, and reconciles only a
matching retained event prefix. It is ordinary execution through the model
command adapter, not prerecorded wire playback or a live-model quality claim.
The optional bounded delay is retained in model options so an installed process
can be killed during a real model dispatch. With nonzero delay, a flushed stderr
`deterministic-dispatch` barrier identifies entry into the actual provider after
model-start journaling; the qualification owner must kill before completion.
Live-model, native-process, remote
and unbound optional adapters remain explicitly unavailable. Native filesystem
publication is available only through the explicitly bound SDK approval plan.
REPL/code-mode and Tree-sitter are outside the original GraphCoder delivery scope.

## Interaction and bounded inspection

- Plain text queues a stock root task. `/parent TASK` selects a real retained
  parent; `/parent root` returns to root admission. Children inherit the actual
  admitted parent context and grants through the public task context.
- `/queue FILE` admits a typed `WorkflowCommand` JSON. Admission and command
  identities are distinct; the attempt identity is flushed before admission.
  `/reconcile OPERATION` observes a lost acknowledgement without resending input.
- `/run TASK` drives this exact task, never an unrelated ready task. Before
  dispatch it flushes `lease-json-hex=...`, the original typed `WorkLease` JSON
  bytes encoded as hex. Decode and retain those bytes externally if exercising a
  process fault. `/resume FILE` consumes that original lease JSON and lets the
  canonical worker verify it; it does not guess or replace ownership.
- Input, queued steering, inspection and `/cancel-task TASK` remain responsive
  while ordinary workers execute. Task cancellation delegates to the original
  typed host and shows the retained admission operation; it requests cancellation,
  never claims the active provider has stopped.
- `/outcome TASK` displays the actual durable outcome and its distinct admission
  operation. `/children FILE` accepts `{task, revision, after}` JSON and reads
  only one direct-child page, at most 16 entries. Continuations must carry the
  observed revision; no complete descendant tree is hydrated.
- `/next` reads one verified activity page. `/cursor FILE` selects an explicit
  Protobuf Resume `ClientFrame` for archival paging. Only one authority cursor is
  accepted; each page is bounded by 16 events and 64 KiB encoded response.
- `/file FILE` and `/read FILE` accept `{caller, lease, file}` with an immutable
  `FileRef`; the original caller fence and byte length are checked before a read
  of at most 64 KiB. `/diff FILE` accepts `{caller, lease, before, after}` and
  displays bounded UTF-8 versions, at most 32 KiB each. `/read-path FILE` accepts
  `{caller, lease, volume, path, generation?}` and requires the caller's genuine
  directory-read grant. Omitted generation reads the current head; an explicit
  generation reads that exact immutable cut, with a provider-enforced 64 KiB
  bound. Foreign source selection uses original allocation generations, never
  silently substitutes a mutable latest head.
  `/write FILE` stages `{caller, lease, volume, operation, path, bytes}` through
  the actual task context with at most 32 KiB of UTF-8 bytes.
- `/claim TASK` retains and starts the original lease without model dispatch.
  `/prepare FILE` admits a typed request with `{operation, parent, caller_lease,
  request}`. `/publish-fork FILE` accepts `{caller, lease, preparation}`, observes
  the genuine report, publishes its seed, and admits its exact declared child.
  The new child agent, source task, preparation task and admission operation are
  displayed separately; an actual budget rejection remains a rejection.
- `/inspect FILE` accepts `{caller, lease, source}` and inspects authorized
  original allocation generations, not source transcript/private adoption.
  `/history FILE` accepts `{caller, lease, cursor}` and reads one canonical owned
  history page, at most 16 events/64 KiB. `/inherited-history FILE` accepts
  `{caller, lease, seed, after_sequence}` and verifies one published inherited
  conversation slice under the exact seed and child authority.
- `/mail FILE` sends `{caller, lease, recipient, operation, payload}` using the
  actual fenced mailbox context. `/inbox FILE` observes `{caller, lease, after}`
  in pages of 16; observation is not consumption. `/queue-mailbox FILE` admits
  `{operation, parent, lease, input}` to the real mailbox-model machine.
  `/checkpoint FILE` observes `{caller, lease}` through the canonical task handle.
- `/publication-open`, `/publication-observe`, `/publication-apply` and
  `/publication-reconcile` consume `{operation_id, caller, caller_lease}`.
  They operate only on the configured original SDK plan and journal; preparation
  does not write back. Apply requires the actual owned interaction resolution
  and preserves edits that violate the original preimage check.
- `/request FILE` submits one already scoped Protobuf `ClientFrame`.
  `/input FILE` requires the conversation-message command discriminator;
  `/approve FILE` requires the exact interaction-resolution command; `/cancel
  FILE` requires a Cancel frame. The same native/WASM codec validates canonical
  bytes, discriminators, protocol and identity. Existing aggregate, fork,
  merge, interaction and coordinator authorities still make the decisions.
- `/reopen` drops the actual provider/runtime handles before opening the same
  composition. It rejects active frontend worker handles instead of silently
  cancelling them. Its success does not imply pending work completed, stopped or
  was resent. Process reopen likewise uses the explicit original config.
- `/back N` displays one transient retained page. Scrollback evicts by both
  count (64 pages) and total bytes (256 KiB). Oversized rendered pages fail
  before output; evicted history requires explicit archival demand.

Transcript, interaction/approval, fork and merge layouts consume the existing
`EventPayload` types. References remain lazy; viewing a ticket grants no response
rights. All provider-controlled terminal controls are escaped. Cancellation
acknowledgement is never labelled confirmed cancellation; admission is never
labelled completion. `/quit` drops presentation without claiming effect
quiescence. `/help` prints the complete control table.

## Explicit playback

`graphcoder --fixture wire [--headless]` reuses the existing
`conformance/native-wasm-event-v2.json`. Its banner always says UI playback only.
`/next`, `/reset`, `/back`, `/request` and `/quit` share the presentation path;
all mutations remain unavailable. Playback is not persistence, recursive
runtime, model, filesystem or grant evidence. It starts at the fixture's
explicit predecessor, not a fabricated missing history.

## Installed and PTY qualification

After integration, the validation owner should run:

```text
cargo test -p acyclic-harness --features terminal,filesystem-local,native-execution --bin graphcoder
cargo clippy -p acyclic-harness --features terminal,filesystem-local,native-execution --bin graphcoder -- -D warnings
cargo install --path rust/crates/harness --locked --features terminal,filesystem-local,native-execution --bin graphcoder --root ABSOLUTE_INSTALL_ROOT
node scripts/test-graphcoder.mjs ABSOLUTE_INSTALLED_BINARY
node scripts/test-graphcoder.mjs ABSOLUTE_INSTALLED_BINARY ABSOLUTE_NATIVE_CONFIG
node scripts/test-graphcoder.mjs ABSOLUTE_INSTALLED_BINARY --full ABSOLUTE_FRESH_SCENARIO_DIR
```

Retain exact source, installed binary and suite hashes, argv, exit status and raw
output. The existing script's pipe/headless checks are installed process evidence,
not PTY evidence. Do not substitute a pipe, mocked terminal or unit test for the
required actual Windows ConPTY / Linux / WSL / macOS PTY interaction.

The `--full` installed lane invokes the same installed binary's
`--prepare-scenario ABSOLUTE_FRESH_SCENARIO_DIR` helper. For a separate actual PTY
lane, invoke that helper directly and use the config path in its returned
`scenario-json` manifest. Do not precreate the same scenario directory before
`--full`. The helper creates actual local providers, an attached source root,
original signed scopes, finite task/model budgets, prepared child admissions,
real history, mailbox payloads and a native publication plan. It emits references
and original leases, not prerecorded outcomes or a second runtime.

The four-agent graph is a logical root, two children and a grandchild. Bootstrap
seed, preparation helpers and mailbox helper are explicitly distinct task roles.
The positive fixture declares 12 total tasks, seven model steps, six active
tasks, concurrency six and task depth three. Nine bootstrap tasks plus one
mailbox helper, one cross-source preparation and its admitted child account for
12. A separate immutable 11-total fixture rejects that final admission; no
budget is raised after admission. The logical root is itself a genuinely prepared
child of the disclosed seed, preserving the required creation proofs.

For an actual installed PTY, launch the absolute installed binary with
`--session CONFIG.json` in the qualification runner's real native PTY (for
example its `pty: true` process option), without `--headless`. Retain all original
typed task, agent, admission-operation and lease identities separately. Exercise
prompt/queued input and scrolling, direct-child paging, original root process
death/resume, mailbox wait and committed one-item consumption, safe-boundary
steering, caller/source-selective history and file access, actual cross-source
preparation/publication/admission, inherited-history/private-scratch isolation,
exact-ref diffs, explicit approval and native writeback with concurrent-edit
preservation. The script's pipe lane supplies process regressions and controls,
but never proves terminal interaction or substitutes its generated fixture for
the public producer APIs exercised by the runtime.

Fault controls: configure a nonzero bounded deterministic delay; kill the
installed process after its flushed original lease claim, reopen with the same
config, and supply that exact retained lease for reconciliation. Negative controls
must include a forged scope/owner, stale generation/revision, wrong command kind,
wrong task identity, altered lease/fence, ungranted file/ref, denied approval,
terminal-control payload and oversized input/page. A timeout/launch failure is
never an acceptable negative-test result. Native producer fault injection owns
interrupted publication, filesystem dispatch and merge acknowledgements; UI code
does not invent such outcomes or automatically repeat them.

No new compile, unit, installed, PTY or platform gate was run during this source
slice. Final-main native/Chromium/WASM and recursive workspace/writeback evidence
remain mandatory for their corresponding claims. The root-to-two-children-to-
grandchild task controls do not by themselves qualify the broader workspace,
context/summary, approval, merge, writeback or cross-platform scenario.
