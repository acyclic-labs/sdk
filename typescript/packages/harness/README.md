# @acyclic-labs/harness

The local `MemoryConversation` byte store retains at most 256 MiB and 65,536 immutable file versions by default, including zero-byte files. `maxResidentBytes` and `maxResidentFiles` configure these local caps; new versions are rejected before retention when either is reached.

TypeScript facade for the Rust-first Harness v2 runtime. It includes typed aggregate handles, reconnect/cursors, bounded hydration, an offline outbox, embedded/JSONL/WebSocket/HTTP-SSE/gRPC transports, explicit conversation selection, and native OpenAI-compatible model projection.

```sh
npm install @acyclic-labs/harness
```

The facade keeps composition small while Rust owns admission. A live local
runtime can be assembled once and receive text or ordered file parts through
the same typed entry point:

```ts
const contracts = await NativeContracts.create();
const runtime = Harness.builder(contracts)
  .limits({ model_steps: 8, attachments: 1024 })
  .grant("model:generate")
  .model(modelIdentity, modelProvider)
  .build();

await runtime.run({
  prompt: "Summarize the supplied file",
  content: [{ kind: "file", file, policy: "bounded_full" }],
});
```

`file` is an already staged, owner-authorized `FileRef`; its bytes never enter
the conversation event or the model request until the selected provider
projection resolves it. Use `MemoryConversation.runConversation` when the
turn must also publish canonical user/assistant history and attachment refs.

Initialize Rust admission once with `const contracts = await NativeContracts.create()`. Build runtimes with `Harness.builder(contracts)`, compose owner-bound readers with `composeContentBindings(contracts, sources)`, and construct a `ParentProjectController(contracts, binding)`. Validate refs, attachment lists, and limits through `contracts.validate(kind, value)`; there are no separate TypeScript validation rules.

`HarnessBuilder.bindings({ ... })` groups independently replaceable runtime providers and delegates to the same checked builder methods. It introduces neither a second task/tool registry nor implicit capability grants.

After an uncertain durable admission, `AgentHarness.reconcileAdmission(operationId)` asks the owner host for the original committed task without resending the input. A confirmed absence returns `null`; a recovered task is checked against the currently pinned definition and output schema before observation or attachment.

Group `race`, `firstSuccess`, and `quorum` observe early outcomes without cancelling or closing remaining members. `cancelOnFailure` is opt-in for both live and durable groups; durable admission requires an owner `cancelBatch` binding and pins the policy in the batch manifest. On a definitive failure, `join` asks the owner to retain one cancellation declaration before requesting accepted members; an uncertain request is exposed as an incomplete group outcome. After restart, `cancelBatchId` loads the exact retained batch and makes the same owner request. The owner must reject later unadmitted members and report each slot separately. A cancellation request is not a terminal outcome; observe the children to learn whether they stopped.

`workspaces(provider)` binds parent-controlled project fork and inspected join operations. The plan exposes exact source and expected target generations and typed conflict, stale, fenced, and applied outcomes; every provider call requires the signed parent scope. A narrowed runtime without project authority cannot retrieve this binding. Filesystem keeps its concrete join plan behind the provider facade.

Use `HarnessBuilder` to register versioned tasks and tools and bind a model, context builder, policy, interaction handler, or replacement loop. Multiple task and tool revisions remain addressable by `name@revision`; an ambiguous unqualified lookup fails, and `selectModelTool(name, revision)` explicitly chooses the one schema exposed to the model. Executable handlers never cross the model boundary. `run(prompt)` is shorthand for the typed input API; the latter accepts ordered text and file parts. Canonical conversation messages carry only immutable `FileRef`s, while `selectModelContext` makes an explicit, revision-pinned model-facing selection. Its `ProjectableConversation` input carries the provider-authoritative `bigint` revision separately from the loaded messages, so compacted or partial remote views do not misstate history length. The reducer exposes `conversationPage(afterSequence, limit)` for bounded history reads; `conversation()` is a convenience that hydrates all pages while checking one stable revision. Use a page's `total_messages`, not its potentially larger `event_revision`, as the model-context revision. `composeContentBindings` routes by exact registered volume, including several owners on one provider; `verifiedContentResolver` adapts that owner-bound binding for model projection. OpenAI and Pi defaults share one bounded, grant-enforcing file projection boundary for text, native PNG/JPEG/GIF/WebP, and opaque references; unsupported content fails before a model request. The Pi bridge also accepts an explicit provider-specific projector. The OpenAI-compatible adapter accepts HTTPS endpoints or explicit loopback HTTP, with no URL credentials, query, or fragment.

`NativeContracts.create(wasm?)` provides an explicitly initialized Rust/WASM validator with exact TypeScript overloads for v2 files, messages, fork values, interactions, and task outcomes. It returns detached, deeply immutable Rust-admitted values, not the untrusted input object. `parseIdentity(kind, value)` brands agent, conversation, session, turn, task, operation, and effect IDs through Rust; `conversationMessageId(value)` does the same for message IDs. Conversation sequence numbers and other full-width `u64` positions remain `bigint`; bounded file lengths and limits become checked JavaScript numbers. Rust also owns `descriptorFor(bytes, mediaType)`, canonical action JSON encoding, and lossless event/history decoding; untrusted model JSON is parsed by Rust and rejected if an integer cannot be represented exactly as a JavaScript number. It also owns byte verification, typed attachment-manifest encoding/decoding, and report-to-seed fork conversion; `resourceRef(value)`, `extensionRecord(value)`, `forkSeed(report)`, `validateForkRequest(request)`, and `validateForkSeed(seed)` are async conveniences over native admission. Their public types retain volume class/owner and resource-kind relationships; generated WASM `any` values stay behind this typed boundary. `Harness.apply` returns an event with an honest unknown payload; `decodeEventPayload(event, parser)` establishes a type only after the commit result is known, so parser failures never obscure whether a command committed. Ref, attachment, and limits admission requires an initialized `NativeContracts` or `Harness` instance; no separate TypeScript validator remains.

Extension state is equally Rust-admitted: `extensionRecord`, `extensionConfiguration`, and `extensionAdmission` validate canonical records, while `extensionStateMigration` validates a migration request without executing it. Native execution remains provider-owned and exact-digest pinned; a durable host must run the registered migration and publish only its resulting `FileRef`. Fork policy is explicit (`inherit`, `reset`, or `reject`), and an admitted task retains the selected extension versions for its entire run so disabling new admissions cannot invalidate reconciliation.

`Harness.apply(command)` also returns `eventWire`, the generated v2 protobuf encoding of the Rust response event. Use it for exact native/WASM comparisons or transport; the projected `event.payload` remains `unknown` until explicitly decoded.

Use `HarnessBuilder.limits({ ... })` to narrow the shared v2 file, path, attachment, rendering, context, model-step, per-step event, and tool-call bounds; Rust/WASM validates canonical messages with those limits before admission and model projection. Grant root capabilities with `HarnessBuilder.grant(...)`; `scoped(ExecutionScope.create().onlyGrants(...))` may only retain a subset, including none. `ExecutionScope.withLimits({ maxSteps })` may narrow the model-step ceiling further for a child scope but cannot widen the builder's ceiling.

`run(prompt)` executes a live local turn even if a durable host is bound. Durable work uses `admit` with a stable operation ID and a versioned resumable task; host-backed contexts require recorded tool, interaction, timer, and child-admission boundaries.

`AgentHarness.children(parent, revision, afterSlot, maximum)` asks the owner-retained state provider for direct task children, independently of conversation forks. Pages are bounded and ordered by stable slot; carry the returned revision into subsequent calls so a changed hierarchy fails explicitly instead of silently skipping a child. The stock coordinator exposes only same-owner children after authenticating the parent.

`HarnessBuilder.execution(provider)` and `ExecutionScope.execution(provider)` select an exact durable placement route for new tasks. An execution provider supplies a compatible state owner and spawner, qualifies the registered task build and accessible inputs, and returns a Rust-validated build/environment/readiness commitment. The owner retains that placement in each task or batch request; reconciliation loads it without re-qualifying against a changed environment. Live JavaScript closures cannot cross that route; remote work requires a registered resumable build admitted with a stable operation ID. The stock local route has `execution: null` and cannot pretend to run a remote build. Providers must explicitly arrange input transfer or mounts and scoped credentials; selecting a remote environment does not make local paths, connections, or secrets available there.

For a local canonical conversation, create `MemoryConversation` for one agent, stage text and attachments with `stage`, and call `runConversation(runtime, operationId, contentRef, attachments)` or `runPrompt(runtime, prompt)`. `MemoryConversation.create({ agent, limits })` sets Rust-validated staging bounds (defaulting to `DEFAULT_LIMITS`); a runtime may narrow them again at message admission. Its `contentBindings()` can also be passed to `Harness.builder(contracts).content(...)`; grant only the owner's read/write capabilities needed by typed tasks and tools, which then use `TaskContext.readFile` and `stageFile`. Attached agents can receive read capabilities without receiving a writer. The host commits ref-only user history and an exact context selection before the model call, then publishes tool call/result artifacts and the assistant reply. More than 128 attachments use Rust's typed canonical manifest bytes, staged and verified before a ref-only event. This host is deliberately process-local: completed operations replay only while its in-memory output cache lives, and an interrupted model dispatch is reported as indeterminate rather than blindly retried. Use a durable host for restart recovery and resumable side effects.

`MemoryConversation.attachReadVolume(owner, delegatedScope)` mounts a known owner's volume read-only; it cannot accept an unscoped callback. `mountReadVolumes({ mount })` resolves previously unseen owner volumes to an owner and scope only when a ref is used, then rechecks that owner's grant on each read. The owner issues a signed exact-file or private-directory grant with `delegateFileRead` or `delegateDirectoryRead`; its `readBindings` enforces that grant on every read. The receiving host checks returned bytes against the pinned digest. Without an owner-issued grant and authenticated reader, foreign refs are unreadable—knowing a path or ref is never itself authority.

The optional `@acyclic-labs/harness-objects` package binds an Objects bucket as the same `ContentBindings` reader/writer boundary. It stages exact versions with stable operation IDs, checks signed owner grants, and never adds an Objects dependency to Harness core.

Default context projection keeps every canonical attachment in storage while passing at most 1,022 attachment refs per message to a model, with an explicit omitted-count marker for the rest. Providers may replace this projection policy without rewriting conversation history.

`HarnessClient` and `ProjectionStore` cover transport and UI projections. Offline-safe commands accept only typed file references and routing metadata; outboxes pin one validated clone and reject inline bodies, bearer scopes, and extra command or authority fields at runtime. In-memory outbox/cursor stores are process-local; use a persistent host for restart recovery. The wire contract is `acyclic.harness.v2`, with no v1 dual-read or migration; a pre-v2 IndexedDB outbox remains untouched but cannot be opened by v2. A future alone is not a durable task.

`ParentProjectController` exposes project fork, merge inspection, Filesystem application, and verified receipt publication through a provider-owned parent binding. The provider authenticates the parent scope on every operation; the facade returns only opaque, controller-owned merge handles and pins the inspected target generation. Apply binds the plan to one Harness operation ID; the provider derives its retry key from that ID, and a receipt for another operation is rejected. After a successful join, `publishProjectMergeReceipt(plan, receipt)` requires that handle, the exact source/target generations, a typed `ProjectMergeReceipt` with a bounded provider operation identity, a bounded provider-owned proof tied to the target workspace provider, and a `ProjectMergeNotice` whose payload is only file refs; the owning host verifies the proof against durable workspace state and atomically appends receipt plus notice to the parent Stream. A child can report changes but cannot publish them into its parent through this API. Fork seeds pin an inclusive inherited-message prefix and the exact clean child-private Filesystem generation, may attach additional reader agents, and carry parent-approved exact-file read grants for references from controlled private, project, and shared volumes; manifest-backed attachment members identify their published list and are checked by the owning provider. Child-owned inherited-context files are also readable by the child and attached agents through exact-file grants. The async `forkReadableReferences` returns the pinned access plan, never a bearer token. Omitted history is not implicitly shared. Foreign private owners must mediate their own bytes. Only the original volume owner writes there. The child conversation still has one owning agent. Conversation history, private volumes, and context never merge implicitly.

Private-directory sharing does not require a fork. `delegatePrivateDirectoryRead` issues a signed reader-bound, segment-bounded capability from the original owner's scope; `directoryReadCapability` computes that same canonical boundary. Storage adapters resolve it lazily at the owner's current generation, and attached agents cannot use it for writes or internal storage paths. `TaskContext.listPrivateDirectory` and `readPrivatePath` use the same owner-authenticated binding, with a pinned generation and ordered cursor; `MemoryConversation` supplies the local default and rejects stale pages. A directory grant may reveal names and current immutable refs, never writable handles.

Durable interaction tickets and resolutions are typed, ref-only values. `interactionTicket` and `interactionResolution` admit their envelopes through Rust; the Rust Stream admission path verifies staged request/answer/decision bytes, the exact responder grant, and compare-and-set versions. Bind an owner-backed `InteractionResolver` separately from the presentation handler to expose `inspectInteraction`, `resolveAnswer`, and `resolveApproval` on the runtime; its replies carry a signed responder scope, exact version, and stable operation ID, and return a typed `ResolutionReceipt`. `TaskContext.interactTyped(questionOrForm, pinnedSchema)` advertises that JSON Schema, validates a returned answer through Rust, then applies its typed parser; non-answer outcomes remain distinct. Approvals bind an operation ID and action digest. Decline, cancellation, expiry, denial, and indeterminate reconciliation remain distinct outcomes. Hosted task contexts require stable operation IDs and a durable host route for interactions and tools; process-local `InteractionHandler` callbacks apply only to live local tasks.

Task requirements use exact bindings such as `task:extract@2` and `tool:search@1`, or a named boundary (`model`, `context`, `interactions`, `policy`, `host`). Build-time validation rejects missing versions and task dependency cycles.

Task code may invoke a registered descendant only with an exact `task:spawn:<name>@<revision>` grant in its effective scope. `TaskContext.task(definition)` returns an opaque typed `TaskRef`, not the child implementation; use that ref with `context.spawn`, `context.admit`, or a context-created task group. The group checks the same grant on batch admission and reconciliation. Scope narrowing can remove individual descendant grants without unregistering the owner's definitions, and self-recursion requires its own explicit grant. Owner-level `AgentHarness` operations remain under the trusted caller's control.

Every tool call requires an explicit `tool:call:<name>` grant, narrowed through child scopes before policy evaluation. A replaceable policy exposes `identity()` with a name, version, and nonzero 32-byte implementation digest (construct it with `policyIdentity`); a durable host reports its enforced identity through `policyIdentity()`. Build and dispatch reject mismatches, including an added scoped policy that the host has not pinned. Scoped policies retain separate, independently approved action decisions. Local approvals carry a Rust-computed canonical action digest and stable operation binding; only an `approved` response permits dispatch. Durable calls always delegate the decision and exact-action approval to the owner host, never the local handler.

There is no implicit built-in tool set: register each versioned tool and its executor explicitly. `defineTool` requires JSON input/output schemas plus typed parsers; the builder admits every pinned task and tool schema through Rust's strict canonical JSON contract, and Rust validates each invocation and result before the parsers admit values to handlers or callers. Model-visible definitions contain schemas only, never handlers. `TaskDefinition.live` runs in the local process via `spawn`; it is not durable. `TaskDefinition.resumable` requires input/output schemas and a typed checkpoint-state schema created with `defineRuntimeSchema(id, nonVacuousJsonSchema, parser)`, an explicit 32-byte implementation digest, a durable host, and async `admit(definition, input, operationId)`; retry an indeterminate admission with the same stable operation ID. A restored state is checked against its JSON Schema and parsed before entering a typed transition. The host owns idempotency, checkpoints, waits, effect reconciliation, and replay. Recovery interfaces return unknown output, never a caller-selected type; the exact pinned definition and Rust JSON Schema check plus typed parser establish the result type. A pending host task keeps `result()` pending; `indeterminate` means a genuinely unresolved terminal outcome. Live `TaskContext.call` returns the typed value; an admitted task uses `callDurable(operationId, tool, input)`, whose typed outcome preserves success, failure, cancellation, or indeterminate reconciliation without retrying an uncertain effect. A durable policy decision requiring approval is handled by the host's exact-action interaction journal; the TS facade does not self-approve or short-circuit that host boundary. `reconcileEffect(effectId)` returns Rust's ref-valued `EffectStatus`, never a caller-invented result type; a successful result must be resolved through the owning content provider. The local runner intentionally refuses to execute resumable transitions, because looping over them in memory cannot provide those guarantees. For retryable batches, pass a stable group ID to `group(policy, id)`, reuse the batch ID, and provide the exact task definition to `reconcileBatch(definition, batch)` through the host's recovery binding. Host-backed task handles expose authoritative event streams and cancellation through `Task.fromHost`, and reattachment checks the pinned task implementation digest and result schema.

`HarnessBuilder.resumableTool(definition, machine)` registers a durable-only tool whose machine name/version matches the definition and whose nonzero implementation digest is admitted by Rust/WASM. The `ToolRef` exposes that pinned identity to the owner state provider without exposing its implementation. Such a tool requires an owner with `executeTool`; local `call` is rejected, while `callDurable` routes the stable operation to the owner for journaled execution and reconciliation. `workflow_admission` is the shared Rust/WASM contract for the exact initial checkpoint and request digest.

Registered `TaskRef` and `ToolRef` values are opaque handles: task code cannot access the child's implementation, tool executor, or inline handler. `TaskContext` and `TaskGroup` keep the raw Harness/content binding private, so file reads remain subject to owner-mediated resolution and scope grants. Direct local approval rejection throws a typed `ToolApprovalError` with its exact outcome and operation identity.

Single-task admission and batch member records now expose the exact Rust-canonical `TaskAdmissionWire` shape, including scoped run limits; state owners attest that value without a second TypeScript admission representation. Durable batch admission publishes one immutable request before admitting any child. The TypeScript host envelope carries `canonical`, the exact Rust-admitted `DurableBatchRequest` value; `inputDigest` hashes only that native shape, and indexed operation IDs use Rust's derivation. The owner retains `canonical`, not the envelope's convenience fields. A single invalid input rejects the whole batch before publication. The spawner returns contiguous indexed decisions and the exact request digest. `HarnessBuilder.state(...)` and `spawner(...)` independently bind retained observation and admission; `host(...)` supplies both by default. With separate providers, every accepted task is checked against the state owner's complete immutable admission record. An unobservable member remains indeterminate without discarding other slots. Repeating `spawnMany` in one group returns recorded admissions without redispatch. `reconcileBatchId(definition, batchId)` loads and validates the owner's retained request when the original inputs are lost; `reconcileBatch(definition, batch)` accepts caller-retained inputs. Only a matching `AdmissionUncertainError` becomes indeterminate after a lost acknowledgement; deterministic provider errors propagate. Host-backed task drivers expose retained terminal events so truncated streams can recover without inventing a cursor. `MemoryConversation` is deliberately volatile: an uncertain local model dispatch is not blindly retried. A durable `HarnessRuntimeHost.executeSelectedTurn` receives the stable operation ID and exact context selection and owns journaled reconciliation. Cross-language host qualification remains pending.

Durable mailbox messages carry a validated `FileRef`, not inline payload bytes. Store and authorize the referenced file before sending; the host owns residency and recipient access checks.

`HarnessBuilder.artifacts(...)` binds immutable artifact storage independently of `content(...)`. `TaskContext.stageArtifact` and `readArtifact` use that provider while retaining exact file verification and the caller's owner-mediated read/write grants.

When a conversation references files from several owners, bind their authenticated readers with `composeContentBindings(contracts, [{ volume, content }, ...])`. An optional third `ContentMountResolver` resolves unknown owner volumes lazily; its owner-bound `requireFileRead` checks each exact ref, and `requireDirectoryPath` authenticates every lazy directory listing or path read. Explicit bindings take precedence, and the fallback supplies only reads, never the composite writer. Routing uses the exact volume and owner identity carried by each `FileRef`, so distinct agents on one provider can be mounted together. The composition never makes a reference itself an access grant.

`HarnessBuilder.forkPreparer(...)` captures parent-selected resources; `forkPublisher(...)` binds a trusted parent-owned publication provider. `AgentHarness.spawnFromReport(report)` validates the complete report and exact Rust-derived seed before requesting publication. The facade checks the provider's returned identity, but cannot independently prove its storage state: a qualified publisher must authenticate both signed scopes, append the exact seed to the parent Stream, and durably bind the fresh child with the correct causal parent before reporting success. If acknowledgement is uncertain, `reconcileSpawn(report)` observes the same operation ID; it never recaptures resources or silently starts another child. Rust's `StreamAggregate::spawn_from_report` is the reference implementation of that trusted boundary.
