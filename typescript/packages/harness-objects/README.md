# Harness Objects adapter

`ObjectContentStore.create` binds one Objects bucket and `VolumeRef<VolumeClass, "objects">` to an exact, trusted provider identity and owner authority. The owning provider supplies `expectedProvider`, `authority`, and `ownerScope`; an attached reader supplies only its signed `scope`. `bindings()` supplies the replaceable Harness content boundary. Each stable upload operation ID pins one complete file contract, including its path; several attachments use distinct stable IDs. Before returning a `FileRef`, staging re-reads the exact retained version and verifies its SHA-256, length, media type, and display name; changed bytes on replay cannot produce a false ref. `loadManifest` validates complete canonical attachment lists and every member. Never take the trusted binding inputs from an untrusted reader. Harness core has no dependency on Objects.
