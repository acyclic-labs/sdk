# Standing proof-entry guard: current scope

Historical HST execution receipts validate their captured source, oracle,
mutants and outputs. They do not require current suite dependencies to retain
the historical hashes. Current inventory references are checked separately, and
the entrypoint guard admits only the exact reporting-module hash exercised by
the captured oracle. Evolving the canonical suite adds no execution or proof
credit. The historical captures remain byte-identical. The two separation
regressions added for this correction are unexecuted under the user policy.

`python scripts/check-proof-coverage.py --base <actual-PR-base-SHA>` checks the committed Rust source delta. The CI caller supplies the real PR base; there is no inferred-base or missing-base success fallback. Dirty tracked trees and uncommitted registries refuse. Git adds and rename destinations require new entries; removed files need no stale proof entry.

The machine registry is `docs/proofs/entrypoint-inventory.json`. It currently registers eleven entries for the HST reporting module, backed by the already admitted real Linux reporting proof and its unchanged-test production guard mutation. Its pass means exact source/invariant/receipt registration. It does not qualify provider behavior or any of the thirty complete cross-mode obligations.

## Decisions

- Reuse one source scanner, `scripts/proof_inventory_scan.py`. The historical read-only inventory driver delegates to it; a second public API walker was not introduced. Effective exports must subsequently join the existing `sdk-docs/src/public_api.rs` rustdoc extractor rather than another Rust API model.
- The [canonical export consumer](canonical-exports.md) now joins real retained DocsData/profile output into17 explicitly unqualified occurrence records across five profiles. Its13 tests and four semantic production-consumer controls cover source/artifact/profile/availability joins. Two additional mutations change refusal reasons while preserving refusal and receive no invariant-acceptance credit. Current-source/profile artifacts, receipt-backed registration integration and generated-source joins remain pending. The earlier fourteen source/coordination captures still provide source review only.
- Every changed Rust source file in the configured stack scopes requires a full-file review entry and exact SHA256, including files with no detected public tokens. This closes silent drift through macros, callbacks or lexical misses while expanded export enumeration remains incomplete. The gate is deliberately conservative about test/support source in those scopes.
- A manifest-only feature change can expose an existing API or unsafe block without changing any Rust file. Root Cargo/lock/toolchain/configuration inputs, and manifests, build scripts, toolchain/configuration and generated schemas in the configured stack scopes therefore refuse until canonical generated-export evidence can be joined. Deletions and the source side of renames are included because removing an input changes inherited defaults or generation. A source-only receipt cannot admit these changes. This is a conservative refusal, not profile qualification or a complete build-input closure.
- Require the exact candidate multiset for source-level public items, detected callbacks, unsafe sites and **all** wildcard arms. Mapper classification cannot be bypassed by renaming a function so it no longer sounds like an error mapper. The source hash invalidates the review when any construct changes.
- Each entry names a concrete invariant and supported receipt adapter. The initial adapter validates the actual HST reporting admission with the existing evidence checker. It admits only the exact reporting module and the availability/refusal invariant. A dependency's presence in a compiled source manifest proves neither that dependency nor another invariant. Unsupported adapters refuse; no generic hash-only receipt or planned-proof fallback exists. New unsafe entries also need a safety argument and a genuine adapter for their safety proof.
- Keep source-registration enforcement separate from complete qualification. The existing `check-wave1-inventory.py --require-qualified` still rejects all thirty open obligations. This source gate also refuses the whole b733-to-current delta because the remaining new Rust sources have no admitted registration. Do not snapshot their signatures into an automatically accepted baseline.

## Evidence and remaining integration

`scripts/test-proof-coverage.py` uses actual admitted HST output, captured production unsafe/wildcard sources with commit/hash provenance, and real temporary git repositories. It does not fabricate git/provider output. Thirteen tests exercise registration, exact candidate counts, invariant/source binding, stale review refusal, real add/rename/delete behavior, dirty trees and typed CLI failure. Five independent production mutations omit the candidate comparison, broaden proof scope to dependency inputs, omit invariant binding, omit unsafe discovery or omit wildcard discovery; unchanged semantic assertions detect each.

This is an incremental source guard. Gate-speed previously authorized a narrow policy-test step in `.github/workflows/static.yml` (reply `gate-speed-to-verify-20261026T031900Z.md`). The user's subsequent compile-only landing policy suspends proof and qualification runs, so this PR removes that added step. The three suites remain available for later authorized qualification. No complete source-registration or runtime guarantee is claimed, and the six unregistered source files and thirty open obligations remain visible.

Gate-speed retains actual-base selection: GitHub uses `github.event.pull_request.base.sha || github.event.before`, fetched explicitly by the existing artifact check; the coordinator candidate uses the sole gate-prepare `.prepared-base` pin. When strict source checking is admitted, pass that exact base to the same checker. Never infer `origin/main`, create a second scanner or invent baseline proof entries to get a green status.

Required full standing-gate work remains: receipt adapters for the domain proofs; effective public exports and profile coverage from canonical rustdoc output; generated RPC/schema registrations; TS/JS/WASM binding and CLI/tool exports; semantic mapper exhaustiveness; invariant changes beyond source discovery; and complete local/cloud proof qualification. CI is not claimed to enforce those pending joins today. No excluded legacy consumer is being proved merely because its source is used as a scanner fixture.

The P1 review fixes include Git type changes in the changed-source fence, so replacing a regular Rust file with a symlink reaches the existing regular-file refusal. The inventory checker also rejects every individual mode marked `qualified` until positive-receipt validation exists. A real temporary-Git symlink regression and single-mode promotion cases are authored but unexecuted under the user's suspended proof-run policy. Historical receipts do not qualify these edits.

These edits and tests await bb2/the existing PR gate; the earlier thirteen-test and mutation receipts do not qualify this revision. Removing the production profile-input guard must make the unchanged feature/removal assertions fail. Independently omitting `--no-renames` must make the unchanged rename assertion fail. No fixture output was fabricated or rewritten.
