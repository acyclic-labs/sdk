## Shared transport semantics audit

The focused source-bound fixture is `research/acceptance/typescript-review/transport-policy-conformance.acceptance.test.ts`, SHA-256 `c9b059749f28589cac3ce74c03465b3eccf16148a6a9b157bf4bd3b460286e3d`. `bun test --timeout 120000 research/acceptance/typescript-review/transport-policy-conformance.acceptance.test.ts` passes 5 tests with 58 assertions. The suite checks that Rust's emitter labels bearer auth and cumulative UTF-8 response limits, that those labels survive into generated metadata tables, and that operation-level adapters are classified by their actual native boundary.

The audit separates shared policy from IO-specific behavior:

- Response bounds and endpoint admission are duplicated in `typescript/packages/actors/src/http.ts`, `workers/src/http.ts`, `machines/src/http.ts`, and `stream/src/http.ts`, while the native Actors, Workers, and Stream HTTP adapters implement the same cumulative body bound. This is shared safety policy that should be emitted or consumed from Rust metadata; the current TypeScript copies can drift in error wording and credential checks.
- Rust Actors and Workers reject credentials containing CR/LF (`rust/crates/actors/src/http.rs` and `rust/crates/workers/src/http.rs`), while their TypeScript constructors currently check only `token.trim()`. The acceptance fixture records this as a live migration gap; a token containing `\\r` or `\\n` is accepted by the TypeScript constructor even though the Rust client rejects it.
- Mutation retry policy is aligned for HTTP: the Rust Stream HTTP adapter documents no automatic mutation retries and the TypeScript HTTP clients contain no retry loop. Rust Stream gRPC intentionally owns a different IO adapter policy in `rust/crates/stream/src/grpc.rs`: a 10-second operation deadline, one-second endpoint attempts, 10 ms retry delay, retryable-status classification, endpoint rotation, and cursor advancement for recoverable follow streams. The TypeScript HTTP `follow` implementation and Rust Stream HTTP `follow` both poll an empty page every 250 ms and fail the operation on a request error; they do not reproduce gRPC failover.
- Abort signals are transport controls. Actors, Workers, Stream, and Harness forward `AbortSignal` into fetch or channel setup, while operation identity, admission, cancellation, and indeterminate outcomes remain protocol policy. The audit found no TypeScript implicit mutation retry or cancellation-to-success conversion.

Filesystem's Rust hosted constructor rejects malformed bearer metadata when it parses `Bearer {token}` as tonic `MetadataValue`; the TypeScript hosted facade now consumes `validateRustOwnedCredentialPolicy` before the handshake. Inference's Rust `authorization` helper rejects newline API keys, and the TypeScript transport now applies the same generated validator before sending a request. The existing package tests witness these rejection paths, and the installed Inference dist witness confirms rejection before fetch. Machines is a separate Rust-WASM route/codec adapter whose canonical remote Rust client requires mutual TLS; its TypeScript HTTP token and response bound are adapter behavior, not evidence of a shared bearer policy. Harness has no remote HTTP facade in the audited wire transport, so it should not be listed as an HTTP capability.

The remaining shared replacement target is generated reuse of Rust response-limit metadata. Retry and streaming recovery should stay adapter-specific: adding gRPC failover to HTTP facades would change the canonical no-implicit-retry behavior.

## Auto-best transport selection audit

The transport-selection fixture is `research/acceptance/typescript-review/transport-selection.acceptance.test.ts`, SHA-256 `0a13277e88381986febf3f793f9db56ac2ad02db60e02aba82bf342348162136`. `bun test --timeout 180000 research/acceptance/typescript-review/transport-selection.acceptance.test.ts` passes 3 tests with 20 assertions. Direct Stream coverage also passes 5 tests with 13 assertions in `typescript/packages/stream/test/transport-selection.test.ts` and `remote-policy.test.ts`.

The Rust selector now has a deterministic native/browser preference table, explicit override validation, and fail-closed `NoCompatibleTransport`/`UnsupportedOverride` errors. Objects and Stream prefer native gRPC, use HTTP JSON in the browser, and preserve streaming and bearer-auth capability metadata. Its source-level contract explicitly rules out retry, downgrade after authorization or application errors, and replay of non-idempotent operations. The acceptance fixture also confirms that the policy does not select native gRPC in a browser runtime.

The TypeScript path now has a working Stream runtime selector: `StreamClient.fromEnv()` chooses the first Rust-qualified option for the detected runtime, accepts an explicit `transport` override, rejects unavailable browser gRPC, and constructs the selected provider. Actors and Workers now expose Rust-emitted static transport policies, but their package sources do not yet expose a corresponding runtime auto-selection entry point. Objects likewise expose policy metadata without a package-level selector. Inference still has no `INFERENCE_REMOTE_POLICY`; Filesystem's browser gRPC-Web policy is absent from generated TypeScript; Machines and Harness have no canonical browser option. The remaining gap is therefore family coverage and shared runtime selection, rather than the earlier claim that TypeScript has no selection API at all.

The selector requirements currently contain only `streaming` and `bearer_auth`. They do not identify the full required operation set, read/write or idempotency requirements, or per-RPC capability coverage, so selection cannot prove that a chosen fallback supports every requested operation. This is a Rust policy-model gap rather than a TypeScript fallback failure.

TLS trust requirements are also not projected. The transport policy contains no CA or trust-root field, while canonical Inference Rust requires HTTPS and a non-empty bounded `ca_pem` in `rust/crates/inference/src/host.rs:81-99`. The TypeScript Inference adapter separately checks HTTPS, but generated metadata cannot express the CA requirement or distinguish that canonical mTLS client from its HTTP adapter. No auth-failure fallback or non-idempotent replay loop was found in the audited TypeScript packages.

The production regeneration check remains red before package comparison: `bun scripts/generate-typescript-packages.mjs check` exits nonzero with `missing Rust-owned contract item: generated output drift: rust/crates/sdk-typescript/prototype/manifest.json`. This is current generator/prototype drift and prevents claiming that the newly emitted transport policy has been installed consistently across packages.
