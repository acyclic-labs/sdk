# Research model observations

Research capture uses the core `research` feature and its shared `model::RESEARCH_CAPTURE_ENABLED` setting. It is disabled in ordinary builds. Provider forwarding features use that same core setting, including when Cargo unifies features through another dependency. Internal raw observations are unredacted; credentials remain in host HTTP headers and are excluded from the body identity.

`executor::ModelRequestBody` format 1 retains the BLAKE3 digest and byte length of the original serialized generation HTTP body. The existing wire serializer hashes each emitted byte as it writes it, including the final request trailer. The fixed observation travels with those same immutable bytes through preparation, generation and pre-acceptance recovery. It is attached to the original `ModelEvent::Completed.metadata["request_body"]`; failed or incomplete response streams do not acquire a completion observation.

Three identities answer different questions. `ModelDispatch::request_digest` identifies the admitted canonical model request. `model::replay_key` is the semantic recording lookup key. `ModelRequestBody::digest` identifies final HTTP body bytes, excluding URL, headers and credentials. Equal Gemini bodies can select different models in their URLs, so equal body digests do not certify equal model admission, cache scope, provider execution or spending. Recorded replay can retain historical body and usage observations without a new HTTP send; these values alone do not establish new spending or current execution ownership.

The original usage producer retains the optional body fact in `ModelUsageRecord` format 3. `ModelUsageProjection` JSONL format 3 uses the same record and existing price interpretation. Admission compares a present body fact to its original terminal metadata, alongside the original operation, step, purpose and reported counters. Missing, malformed or unsupported body observations remain unknown. An admission without a completion has no body observation. The reader does not reconstruct HTTP bytes or substitute either other request key.

The six-table Arrow/Parquet layout is version 3. `model_calls.request_body_digest` is lowercase BLAKE3 hex and `request_body_bytes` is the original byte length; both remain null without the fact. The shared PROV-O writer retains these as observation properties. Inspect retains the same typed usage and original terminal metadata. Earlier usage layouts are refused; saved earlier table layouts must be reprojected from their original sources. Union shards only within the same table and schema version; copying columns or filling missing fields with null does not upgrade source guarantees. No migration or second collector is provided.

The encoder retains fixed hash state; request bytes and metadata still scale with this one admitted request. Enabled capture adds one streaming hash of the body, without another serialization, body buffer, source read, provider round trip, clock, wait, task, journal publication or durability barrier. Native completion extends its existing allocation admission for the fixed metadata graph and transfers surviving capacity with the original event. Research-only producer state is zero-sized when the core mode is off. Offline file publication and durability remain with the caller's existing volume commit.

Contributor checks can target the changed boundary with `cargo check --locked -p acyclic-harness-providers --tests --features research` and `cargo check --locked -p acyclic-harness-core --tests --features research,filesystem,metrics-export,provenance-export`. Existing generated serialization controls compare the digest with final output bytes, while the real socket recovery control checks the actual submitted body through both portable and native paths. Existing immutable-journal and Arrow/Parquet controls cover mismatch refusal and format separation. These commands describe how to validate the change, not an assertion that they have been run.

The kept `model_observations` fuzz target calls the public body decoder and the original event and usage JSON decoders. It checks canonical round trips and refuses unsupported body versions and malformed digests. Compile it with `cargo check --locked -p acyclic-sdk-fuzz --no-default-features --features model-observations --bin model_observations`. From `rust/fuzz`, run it with `cargo +nightly fuzz run model_observations --no-default-features --features model-observations`. This exercises observation decoding, not terminal admission or provider execution. Generated metadata and scripted socket replies also cannot qualify preservation of captured provider metadata through the deployed provider, executor and journal path.
