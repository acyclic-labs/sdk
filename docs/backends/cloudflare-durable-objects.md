# Cloudflare Durable Objects

Use `@acyclic-labs/harness/cloudflare` with SQLite-enabled Durable Object classes. Initialize the shipped harness Wasm module once in the worker (`initSync` with a statically imported Wasm module). Call `openCloudflareLedger(ctx, wakeActor, limits)` in a ledger DO and `openCloudflareAgent(ctx, ledgerStub, ctx.id.name, options, owner, registry)` in each named agent DO. Each agent DO owns exactly one actor. The ledger is a Stream consistency domain shared by actors that need atomic publication and forks.

Forward the ledger's `register`, `dispatch`, `open`, immutable-object RPC methods and `alarm` through a private DO binding. Forward an agent's `create`, `send`, `cancel`, `archive`, `pause`, `read`, `readFile` and `wake`; its alarm calls `wake`. The executable [qualification worker](../../rust/crates/conformance/cloudflare/worker.ts) demonstrates the complete binding composition. Its model callback is a deterministic test provider; applications inject their own model registry and authority custody.

The controller opens `AgentGuest.open` with host-injected providers and hosts that guest through the canonical wire handler and `AgentHost::hosting`. An event drains committed inputs through finite reads and releases the actor before returning. No detached Rust scheduler or passive subscription is required to keep an agent alive. Control commits can enter the canonical inbox while a guest is running, so cancellation can abort that turn. Delivery stays serialized, and generation-fenced alarm updates preserve recovery for later controls. Committed actor timers become DO alarms. Ledger wake intents are inserted in the same SQLite transaction as their Stream command, routed only to registered state/inbox paths, acknowledged with a generation fence, and retried by a durable alarm. No input gate spans an outbound actor wake RPC.

The shared `JournalStream` accepts configure, flush, read and append-if-sequence journal primitives; `SqliteJournal` persists canonical commands in bounded chunks; the shared Rust Stream state machine decides conditions, retry identity, forks, filters and receipts. A command is durable before its result becomes visible. Closing every provider discards its replay cache; reopening rebuilds it from SQLite. The immutable object provider verifies canonical filesystem hashes and bounds before returning bytes. Its authority lives on the same Stream domain, allowing the existing filesystem spawn participant to join child-volume creation to the actor transaction. Spawned children stay inactive until their named DO explicitly calls `adopt(childPath)`.

The storage port is open: `WasmAgentProviders.injected(stream, objects, durable, options)` accepts any Stream handle and JavaScript immutable `length`, `read`, `put` promise methods. `put` must finish durability before resolving. DO storage does not require adding a guest storage enum variant.

Limits are explicit: retained commands/bytes, canonical Stream capacities, actor registrations (bounded by the domain's path capacity), object size, and turn budgets. Journal and immutable objects have no compaction or garbage collection in this adapter. Size domains accordingly; this bounded replay implementation is not an unbounded ledger. Domain limits are persisted and must remain identical on reopen. The injected bindings are trusted storage/control interfaces; expose authenticated application endpoints separately. An actor's named placement and initial prompt are immutable; a second DO cannot register the same actor paths. Use a new named DO and creation intent for a different root. All filesystem volumes involved in an atomic spawn must use the same ledger.

Browser composition also uses its agent Stream for filesystem authority now; `filesystem_database` retains immutable objects. Profiles produced by the older experimental split-authority browser layout require an explicit migration before reopening. This adapter does not silently reinterpret them.

The Cloudflare adapter is 245 lines: 29 for binding composition and 216 for SQLite I/O, chunk encoding and integrity checks. Replay, limits, idempotency, cursor lifetime, wake routing and control/delivery coordination live in the shared Rust journal and `@acyclic-labs/harness/hosting` event core. The same event core accepts any synchronous metadata store with a durability promise and an alarm primitive; it contains no Cloudflare API calls.

Run on bb2, without provider accounts or credentials:

```sh
pwsh -NoProfile -File Q:/lanes/bs.ps1 bash -c 'bash scripts/qualify-cloudflare.sh'
```

The runner uses the workerd binary installed by the pinned Miniflare toolchain with a direct public Cap'n Proto configuration. Its only listener is `127.0.0.1:15420`, and it stops/reaps the process between restart checks and at run end. Direct workerd avoids Miniflare's unconfigurable ephemeral Node loopback listener. It compiles both Wasm artifacts, type-checks the adapter, and executes the unchanged Stream and AgentHost suites inside workerd/Miniflare, first directly on SQLite and then across real DO RPC with pull-based cursors. The host crash vectors interrupt every provider API boundary in their deterministic replay program; they do not inject torn SQLite pages or claim arbitrary crash coverage for every model/tool program. Separate integration checks run a real guest turn, verify its filesystem output, replay create/send intents, keep two agents' wake routing independent, abort a stalled real guest/model callback at the host timeout without consuming input, cancel a separately stalled guest through its committed inbox, then dispose the whole emulator and reopen its persisted SQLite directory. Exact replay must retain the same single conversation record.

On bb2 (2026-10-27), both unchanged suites passed in pinned workerd: 3.303 seconds directly on SQLite and 16.428 seconds across actual DO RPC. The normal packaged harness artifact passed exact create/send replay, filesystem-output reads, independent actor wakes, timeout abort, cancellation through the committed inbox, and replay after a full persisted emulator restart. The adapter also passed strict TypeScript checking.

No live-account steps are needed for local qualification. Deployment requires the application's Workers bindings, SQLite DO migrations, Wasm initialization, authority custody and model configuration; these are intentionally application-owned.
