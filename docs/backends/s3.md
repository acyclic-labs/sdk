# S3-compatible blob storage

Enable `acyclic-objects/s3`. Build an `object_store::aws::AmazonS3` for a private
bucket with `S3ConditionalPut::ETagMatch`, then compose the canonical blob engine:

```rust,ignore
let medium = S3Medium::new(bucket, "application", capabilities)?;
let objects = Store::new(medium).account(b"verified-account")?;
let filesystem_objects = LogicalObjectStore::new(Arc::new(objects));
```

`bucket` implements `s3::Bucket`: `ObjectStore`, `Signer` and `MultipartStore`.
The supplied signer must bind additional query parameters and headers. Install
the application's Rustls provider once before constructing the bucket. Use the
SDK's Ring configuration, or the provider already selected by the application.
Pass the same concrete Postgres Stream provider to `StreamAuthorityStore` and
hosting placement; filesystem has no backend-specific dispatch.

## Capabilities and physical operations

Pass explicit `s3::Capabilities`. Conditional writes, conditional delete,
read-after-write, ranged reads and lexical listing are required; construction
fails before I/O if any is absent. `Capabilities::REQUIRED` asserts all supported
operations and must only be used for a qualified endpoint. No vendor names are
inspected. `multipart` selects conditional multipart upload for bodies larger
than 5 MiB; disabling it selects a single conditional PUT, subject to the
provider's single-request size limit.

Small creates use `If-None-Match: *`. Larger creates upload uniform parts of at
least 5 MiB, enlarged to stay within 10,000 parts,
and sign `CompleteMultipartUpload` with `If-None-Match: *`. An HTTP 200 error
XML document is an unknown outcome, never success. A failed upload aborts its
own upload ID; it never deletes the destination to compensate for an uncertain
completion. Caller cancellation may leave an unfinished upload for provider
lifecycle cleanup. Conditional replacement and removal compare the observed
bytes, then bind `If-Match` to their opaque ETag. Conditional DELETE is an
additional requirement of the current blob engine; plain DELETE cannot replace it.

The shared `Store` owns account isolation, BLAKE3 identity, verification,
retained references, manifests, collection and batch semantics. Physical keys
under each account include immutable versioned payloads (`p/`), current envelopes
(`e/`), retained roots (`r/`), inbound references (`i/`) and collection/admission
revisions (`g/`, `a/`). There is no namespace snapshot or historical body replay.
Selected reads fetch the current envelope and selected payload ranges.
Collection's documented stalled-publication and abandoned-reference limitations
remain those of the shared engine; the adapter adds no private index or collector.

## Provider differences

| Provider | Configuration and qualification boundary |
| --- | --- |
| MinIO | Explicit endpoint, local region and path-style addressing. HTTP is confined to the disposable loopback emulator. Qualify the deployed version's conditional completion and DELETE. |
| AWS S3 | Use the bucket region and authenticated HTTPS. General-purpose buckets document conditional writes/completion and `If-Match` DELETE. Versioned bucket deletion can retain older physical versions; the adapter does not purge versions. [Conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html), [DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html). |
| Cloudflare R2 | Account endpoint and region `auto`. Use equal nonfinal multipart part sizes and the authenticated S3 endpoint. Its compatibility table documents conditional PUT; qualify conditional completion and DELETE explicitly before asserting capabilities. [Compatibility](https://developers.cloudflare.com/r2/api/s3/api/), [consistency](https://developers.cloudflare.com/r2/reference/consistency/). |
| Tigris | Configure the deployment endpoint/region. Documented conditional operations do not substitute for a run of the engine's exact conditional-delete and completion races. Qualify the intended location topology and independent clients without sleeps. [Conditionals](https://www.tigrisdata.com/docs/objects/conditionals/), [consistency](https://www.tigrisdata.com/docs/concepts/consistency/). |

## Live steps

On bb2 provision a disposable MinIO bucket and Postgres database under `/mnt/bb`,
bound to `127.0.0.1:15400-15499`. Run
`scripts/backends/storage-conformance.sh`, stopping both emulators on exit.
Record source, server version, suite timings and physical request observations.
The fixture assumes immediate read-after-write; do not add consistency sleeps.

For live S3/R2/Tigris, the coordinator supplies a private disposable bucket and
`STORAGE_S3_ENDPOINT`, `STORAGE_S3_REGION`, `STORAGE_S3_BUCKET`,
`STORAGE_S3_ACCESS_KEY`, `STORAGE_S3_SECRET_KEY`, `STORAGE_POSTGRES_URL` without
printing credentials; leave `STORAGE_S3_ALLOW_HTTP` unset. Run the same executable:

```sh
cargo run --locked -p acyclic-conformance --features storage-backends --bin storage-conformance
```

Use independently opened clients, including each intended client region. Capture
one-winner create/replace races, delayed conditional removal against recreated
bytes, both stale and valid multipart completion, immediate visibility, and
first/middle/suffix/empty/unsatisfiable ranges. Retain status codes, opaque ETags,
actual successful part counts, topology and timings. A missing conditional
operation fails qualification; never advertise a capability based on a vendor
name. Remove the disposable prefix and unfinished uploads after stopping writers.
