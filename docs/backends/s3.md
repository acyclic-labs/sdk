# S3-compatible Objects

Enable `acyclic-objects/s3`. Provision a private physical bucket, construct an
`object_store::aws::AmazonS3` with its endpoint/region/credentials, and pass it to
`acyclic_objects::s3::S3Objects::open` with an exclusive storage prefix and explicit
`Capabilities`. The adapter never inspects a vendor name. Use
`S3ConditionalPut::ETagMatch` on the S3 builder.

Compose with `LogicalObjectStore::new(Arc::new(objects), logical_bucket)` and any
`StreamAuthorityStore` through `Fs::new`. No filesystem changes are required.
Logical buckets live inside the provisioned physical bucket; the adapter does not
need account-wide bucket creation/deletion permissions.

The shared logical Objects core owns validation, conditions, retry receipts,
multipart assembly, range selections, and listing semantics. The adapter stores
immutable, checksummed commands, including bodies and sampled timestamps, then
publishes a small head with `If-Match`. Initialization uses `If-None-Match: *`.
Only published commands reach the core. Clones share one HTTP pool and cache.
Large command bodies use uniform 5 MiB multipart parts; only the final part may
be smaller. Ranged GETs bound recovery reads when enabled.

Limits: current data and staged bodies use the unchanged core memory defaults
(64 MiB, 10,000 entries). Recovery replays retained commands; history and orphaned
CAS candidates are not yet compacted. A prefix serializes mutations through one
head, so provision separate prefixes for independent tenants and account for
endpoint per-key write throttles. Eight lost publication races return Unavailable;
retry the same mutation identity. Conditional PUT and read-after-write are
required capabilities; disabling either returns Unsupported. Multipart and range
flags select transport mechanisms, without changing logical semantics.

## Provider differences

| Provider | Configuration and differences |
| --- | --- |
| MinIO | Explicit endpoint, path-style addressing, local region; HTTP only for the disposable emulator. Validate the deployed server's conditional PUT behavior. |
| AWS S3 | Use the bucket's region and authenticated HTTPS. General-purpose buckets support conditional PUT and multipart completion; multipart initiation/parts do not accept those conditions. Physical ETags remain opaque. [AWS conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html). |
| Cloudflare R2 | Account endpoint, region `auto`. Uniform nonfinal multipart part sizes are required. Avoid cached public domains; the S3 API supplies atomic conditional writes and strong consistency. Observe per-key throttling. [S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/), [multipart limits](https://developers.cloudflare.com/r2/objects/upload-objects/), [consistency](https://developers.cloudflare.com/r2/reference/consistency/). |
| Tigris | Endpoint `https://t3.storage.dev`, region `auto`. Single-region and Multi-region location types provide strong cross-region reads; Global and Dual-region can return stale cross-region reads and cannot advertise this adapter's read-after-write capability for that topology. [Consistency](https://www.tigrisdata.com/docs/concepts/consistency/), [conditional operations](https://www.tigrisdata.com/docs/objects/conditionals/). |

## Live steps

The coordinator provisions an empty private bucket and injects
`STORAGE_S3_ENDPOINT`, `STORAGE_S3_REGION`, `STORAGE_S3_BUCKET`,
`STORAGE_S3_ACCESS_KEY`, `STORAGE_S3_SECRET_KEY`, and a disposable
`STORAGE_POSTGRES_URL` without committing or printing them. Leave
`STORAGE_S3_ALLOW_HTTP` unset. Run on bb2:

```sh
cargo run --locked -p acyclic-conformance --features storage-backends --bin storage-conformance
```

Repeat using independently opened clients and, for Tigris, each relevant client
region. Verify immediate create/update/delete reads, one winner in concurrent
If-None-Match and If-Match races, exact multipart completion/retry, and first,
middle, suffix, empty and unsatisfiable ranges. Retain response codes, opaque
ETags, service version, region/topology and suite timings. Do not add consistency
sleeps to the fixture: stale reads fail qualification. Clean up the disposable
physical prefix/bucket and unfinished multipart uploads after evidence capture.
