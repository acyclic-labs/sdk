# S3-compatible Objects

Enable `acyclic-objects/s3`. Provision a private physical bucket, construct an
`object_store::aws::AmazonS3` with its endpoint/region/credentials, and pass it to
`acyclic_objects::s3::S3Objects::open` with an exclusive storage prefix and explicit
`Capabilities`. The adapter never inspects a vendor name. Use
`S3ConditionalPut::ETagMatch` on the S3 builder.

For a direct `object_store` dependency, disable default features and enable
`aws-base`, `reqwest` and `ring`. The adapter enables HTTPS with the SDK's Ring
provider; `object_store`'s bundled `aws` feature would also enable AWS-LC and
make automatic Rustls provider selection ambiguous.
Before constructing the S3 builder, the application installs its provider once:
`rustls::crypto::ring::default_provider().install_default()` (handle the result,
or use the application's already-installed provider). `rustls-no-provider`
requires that application initialization explicitly.

Compose with `LogicalObjectStore::new(Arc::new(objects), logical_bucket)` and any
`StreamAuthorityStore` through `Fs::new`. Native hosts use the filesystem's
existing `CachedObjectStore` and `staged_objects::StagedObjects` stack above that
logical store, as the local filesystem does. Staging flushes bounded immutable
batches before authority publication; it does not acknowledge unpublished data
as durable. No filesystem changes are required.
Logical buckets live inside the provisioned physical bucket; the adapter does not
need account-wide bucket creation/deletion permissions.

The shared logical Objects core owns validation, conditions, retry receipts,
multipart assembly, range selections, and listing semantics. Publication stages
an isolated copy-on-write core, persists current metadata pages and immutable
body references, and atomically publishes their root with `If-Match`.
Initialization uses `If-None-Match: *`. Only a successful root CAS makes the
candidate visible. Caller cancellation cannot interrupt an owned publication.
Clones share one HTTP pool and current-state cache.

## Decisions

LocalObjects and S3 use the same extracted `memory::durable` record codec,
checkpoint traversal and recovery validators. Physical body restoration is the
transport input to that codec. `StoredBody` already performs asynchronous
nonresident reads; immutable remote leaves use that path. Opening a provider
loads only retained metadata pages. A selected read fetches the selected bytes
of the current body, including multipart leaf intersections; it never replays
superseded bodies. Large physical bodies use uniform 5 MiB multipart parts, with
only the final part smaller.

The shared `memory::remote::publication::Publisher` owns conditional-root
coordination, staging, contention retries and batch publication. S3 supplies only
physical reads, writes and opaque conditional-write versions. An ordered Objects
PUT batch runs through the canonical core once and publishes its successful
items and retry receipts under one root CAS. Per-item failures retain the same
ordered results; an unsuccessful root publication exposes no candidate state.
The durable root and metadata formats are unchanged.

The same shared persistence core uploads independent immutable bodies in bounded
groups of eight. It waits for every body before encoding and publishing the
metadata root. Upload completion order cannot publish a partial candidate;
the conditional head remains the sole publication point.

Retry identities are global across logical buckets in one provider namespace.
One conditional root preserves that authority. Separate prefixes are independent
authorities; endpoint per-key write throttles apply to each namespace root.

Limits: the unchanged core capacity defaults are 64 MiB of current/staged body
lengths and 10,000 entries, including retry receipts. Body bytes are nonresident
after publication. Current metadata is loaded into the persistent core on cold
open; cold-open metadata and snapshot encoding cost depend on retained entries,
including multipart references, not historical writes. Snapshot pages target
64 KiB with the existing local checkpoint hard record bound of 2 MiB. Reusable pages and bodies are content
addressed. Unreferenced CAS candidates and older immutable roots/pages/bodies
remain in physical storage; this adapter does not yet collect them. Do not apply
age-based expiration to referenced immutable data. Delete an entire disposable
namespace only after stopping its writers.

Eight lost publication races return Unavailable; retry the same mutation
identity. Conditional PUT and read-after-write are required capabilities;
disabling either returns Unsupported. Multipart and range flags select transport
mechanisms without changing logical semantics. With ranges disabled, the
transport fetches the selected current leaf in full, then slices locally.

## Provider differences

| Provider | Configuration and differences |
| --- | --- |
| MinIO | Explicit endpoint, path-style addressing, local region; HTTP only for the disposable emulator. Validate the deployed server's conditional PUT behavior. |
| AWS S3 | Use the bucket's region and authenticated HTTPS. General-purpose buckets support conditional PUT and multipart completion; multipart initiation/parts do not accept those conditions. Physical ETags remain opaque. [AWS conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html). |
| Cloudflare R2 | Account endpoint, region `auto`. Uniform nonfinal multipart part sizes are required. Avoid cached public domains; the S3 API supplies atomic conditional writes and strong consistency. Observe per-key throttling. [S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/), [multipart limits](https://developers.cloudflare.com/r2/objects/upload-objects/), [consistency](https://developers.cloudflare.com/r2/reference/consistency/). |
| Tigris | Endpoint `https://t3.storage.dev`, region `auto`. Single-region and Multi-region location types provide strong cross-region reads; Global and Dual-region can return stale cross-region reads and cannot advertise this adapter's read-after-write capability for that topology. [Consistency](https://www.tigrisdata.com/docs/concepts/consistency/), [conditional operations](https://www.tigrisdata.com/docs/objects/conditionals/). |

## Validation

The [PostgreSQL backend validation commands](postgres.md#validation) run
`scripts/backends/storage-conformance.sh` on bb2 with its explicit input declaration.
The runner creates disposable MinIO and PostgreSQL containers under `/mnt/bb`, then
calls the unchanged canonical conformance exports. On bb2, 2026-10-26, Objects
passed in 409 ms and Stream in 121 ms. Independent-client conditional races,
immediate create/update/delete reads, physical multipart, ranges and exact
reopened receipts passed in 687 ms. Filesystem smoke over both providers passed
in 194 ms; a 256 KiB chunked-file check read exact bytes after fresh providers
reopened in 257 ms. The combined storage executable took 2.022 s.

A response observer consumed and counted actual MinIO GET bodies. After both
one and eight 1 MiB overwrites, fresh open fetched zero body objects; a one-byte
suffix fetched exactly one body byte in one GET. Open plus selection transferred
470 bytes of current metadata in both samples. The prior bodies were not read.
The full Objects library regression run with `local,s3` passed 86 tests in
3.81 s (two existing measurement tests ignored), including checkpoint bounds,
recovery, multipart and LocalObjects conformance.

## Live steps

The coordinator provisions an empty private bucket and injects
`STORAGE_S3_ENDPOINT`, `STORAGE_S3_REGION`, `STORAGE_S3_BUCKET`,
`STORAGE_S3_ACCESS_KEY`, `STORAGE_S3_SECRET_KEY`, and a disposable
`STORAGE_POSTGRES_URL` without committing or printing them. Leave
`STORAGE_S3_ALLOW_HTTP` unset. Run on bb2:

```sh
cargo run --locked -p acyclic-conformance --features storage-backends --bin storage-conformance
```

Repeat using independently opened clients and, for Tigris, each relevant client
region. Verify immediate create/update/delete reads, one winner in concurrent
If-None-Match and If-Match races, exact multipart completion/retry, and first,
middle, suffix, empty and unsatisfiable ranges. Retain response codes, opaque
ETags, service version, region/topology and suite timings. Do not add consistency
sleeps to the fixture: stale reads fail qualification. Clean up the disposable
physical prefix/bucket and unfinished multipart uploads after evidence capture.
